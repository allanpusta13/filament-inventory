## CRITICAL SECURITY & PERFORMANCE GUARDRAILS (MANDATORY)

### Guardrail 1: Role-Scoped Data Masking
- **Admin/Auditor roles**: Display interactive "Filter by Warehouse" dropdown in dashboard header. Allow warehouse selection and cross-warehouse analytics.
- **Branch Managers/Staff roles**: 
  - Completely hide the warehouse dropdown
  - Detect user's assigned warehouse pivots from DB (`user.warehouses()` relationship)
  - Hard-scope ALL queries to user's warehouse IDs
  - Return empty dataset if user has no warehouse assignment
- **Sensitive Data Exclusion**: The "30-Day Material Loss" write-off metric (and all dollar totals) must be completely hidden from lower roles. Only non-financial physical stock counts visible.

### Guardrail 2: Aggregation Caching (5-Minute TTL)
- Wrap ALL database aggregates (on-hand sum, in-transit count, loss write-offs) inside `Cache::remember()`
- TTL: 300 seconds (5 minutes)
- Cache key must be dynamic, scoped to active warehouse filters:
  ```php
  $cacheKey = 'stats_overview_' . ($warehouseIds ? implode('_', sort($warehouseIds)) : 'all');
  ```
- Purge cache on relevant model updates (inventory, requisitions, write-offs) using `modelObserver` or `afterSave` hooks

### Guardrail 3: High-Precision Financial Formatting
- All financial metrics (losses, valuations) rendered with 4-decimal-place precision
- Format: `formatNumber($value, 4)` or custom `number_format($value, 4, '.', ',')`
- Example: `$1,250.0150` (not `$1,250.02`)
- Rationale: Aligns with base-unit ledger decimal scheme in system

## DESIGN SPECIFICATIONS

### Glassmorphic CSS Utilities
All glass panels must use this foundation:

**Light Mode**:
```css
.glass-panel {
    background: rgba(255, 255, 255, 0.03);
    backdrop-filter: blur(24px) saturate(120%);
    -webkit-backdrop-filter: blur(24px) saturate(120%);
    border: 1px solid rgba(255, 255, 255, 0.08);
    box-shadow: 0 8px 32px 0 rgba(0, 0, 0, 0.05);
}
```

**Dark Mode**:
```css
.dark .glass-panel {
    background: rgba(10, 10, 10, 0.15);
    backdrop-filter: blur(24px) saturate(140%);
    -webkit-backdrop-filter: blur(24px) saturate(140%);
    border: 1px solid rgba(255, 255, 255, 0.04);
    box-shadow: 0 8px 32px 0 rgba(0, 0, 0, 0.15);
}
```

**Accent Variant (Error/Loss Cards)**:
```css
.glass-accent-red {
    background: rgba(239, 68, 68, 0.04);
    border: 1px solid rgba(239, 68, 68, 0.15);
    box-shadow: 0 8px 32px 0 rgba(239, 68, 68, 0.05);
}
```

### Interactive Transitions
All cards must respond smoothly to user interaction:
- Hover scale: `hover:scale-[1.01]` (subtle 1% lift)
- Hover translate: `hover:translate-y-[-2px]` (micro-elevation)
- Shadow elevation: `hover:shadow-2xl` (depth increase)
- Transition class: `transition-all duration-300`

### Grid Layout (Bento Responsive)
- **Mobile (default)**: 1 column
- **Small (sm:)**: 2 columns
- **Large (lg:)**: 4 columns
- Use Tailwind's `grid` + `col-span-*` for asymmetrical card layouts (e.g., one stat card spans 2 columns on desktop, 1 on mobile)

- Row actions: Approve, Reject, View Details

**Data Masking Example**:
```php
protected function getTableQuery(): Builder
{
    $user = auth()->user();
    $query = Requisition::query();
    
    if (!$user->hasRole(['admin', 'auditor'])) {
        $warehouseIds = $user->warehouses()->pluck('id');
        $query->whereIn('from_warehouse_id', $warehouseIds)
              ->orWhereIn('to_warehouse_id', $warehouseIds);
    }
    
    return $query->with(['fromWarehouse', 'toWarehouse', 'items']);
}
```
