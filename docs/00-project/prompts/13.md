# Phase 13: Eager-Loading Optimization & Security Throttling (v3.0)

## Objective
Audit N+1 query patterns across resource listings by overriding `getEloquentQuery()` and applying rate limiting middleware to QR scan endpoints.

---

## Eager Load Overrides (`getEloquentQuery()`)

* **`ProductResource`**: `parent::getEloquentQuery()->with(['variants', 'variants.unitConversions'])`
* **`TransferRequisitionResource`**: `parent::getEloquentQuery()->with(['fromWarehouse', 'toWarehouse', 'requestedBy', 'items.productVariant'])`
* **`DirectTransferResource`**: `parent::getEloquentQuery()->with(['productVariant', 'warehouse', 'relatedMovement', 'creator'])`
* **`InTransitResource`**: `parent::getEloquentQuery()->with(['transferRequisition.fromWarehouse', 'transferRequisition.toWarehouse', 'productVariant'])`
* **`StockMovementResource`**: `parent::getEloquentQuery()->with(['productVariant', 'warehouse', 'creator'])`
* **`LossLedgerResource`**: `parent::getEloquentQuery()->with(['transferRequisition', 'productVariant', 'warehouse'])`
