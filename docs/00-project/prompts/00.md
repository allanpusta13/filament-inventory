## 🧭 Part 1: Operational Guidelines & Directives

### 1. Unified Architectural Guardrails
1. **Micro-Pricing Precision**: All unit costs, selling prices, price overrides, and financial write-offs must be stored in database fields of scale `decimal(12,4)` (or `decimal(15,4)` for aggregates). Real-time monetary values must not be truncated in calculations.
2. **Pure Derived Stock**: Never store physical stock counts or reservation balances in physical database columns (e.g. `WarehouseStock`). On-hand, reserved, and available quantities must be calculated dynamically at query-time from the immutable `stock_movements` ledger and active requisitions.
3. **Ledger Immutability**: Stock movements, loss logs, and negotiation histories are append-only. Once written, they must never be edited, deleted, or soft-deleted. Corrective transactions must be entered as balanced, reversing adjustments.
4. **Dialog-Based Wizards**: All stock transfer pipelines (both Requisitions and Direct Transfers) must be configured as fast, in-page Dialog Modals of width `3xl` that apply `->closeModalByClickingAway(false)` to prevent floor operators from losing scanned data.
5. **Validation Against Negatives**: Forms, API endpoints, and services must enforce strict validation checks ensuring that quantity values are positive integers strictly greater than zero.
6. **No Skip-at-Receipt**: If expected dispatched items are omitted from a physical receipt payload, they must not be skipped. They must be logged as `0` received, triggering a 100% shortage write-off on the Loss Ledger.
7. **Canonical 4-Role RBAC**: System permissions are bound strictly to exactly four roles cast via a typed PHP `UserRole` Enum: `admin`, `auditor`, `branch_manager`, and `warehouse_staff`.
8. **Relational Eager-Loading (N+1 Guard)**: All Filament resource listings must override `getEloquentQuery()` and declare explicit relationships (`with()`) to achieve a flat query footprint.
9. **Clinical UI Density**: Interface views must prioritize flat borders over decorative shadows, avoid browser-native font variations, and remove alternating row zebra-striping, using quick hover highlights instead (`hover:bg-zinc-50`).
10. **State Isolation Testing**: Unit and feature test suites must run on isolated, in-memory SQLite configurations. Headless browser E2E workflows run sequentially on isolated PostgreSQL containers with database resets before each run.

### 2. Consolidated MUST & NEVER Directives
*   **MUST** relocate all Filament resources into the v5 nested structure: `app/Filament/Resources/{ModelName}/{ResourceName}.php, Pages/, RelationManagers/, Schemas/, Tables/, Widgets/}`.
*   **MUST** run code-formatting checkups (`./vendor/bin/pint`) before committing any file.
*   **MUST** verify that refactoring actions are behavior-preserving by executing `vendor/bin/pest` and `npx playwright test` immediately before and after.
*   **MUST** sum dynamic stock counts directly from `stock_movements` rather than reading from a physical cached database table.
*   **NEVER** modify or rename files inside the read-only `docs/00-project/prompts/` directory.
*   **NEVER** run `php artisan serve` in the Envkit environment; APP_URL is managed via the local test server.
*   **NEVER** write or execute direct raw database mutations outside atomic Eloquent transactions on the service layer.

### 3. Stop-and-Confirm Checkpoints
The autonomous agent must list exact file diffs and wait for user confirmation before executing:
1. Deleting or overwriting pre-existing files that conflict with the map.
2. Any destructive database operations (`migrate:fresh`, `truncate`, `drop`).
3. Introducing new third-party composer dependencies not already approved in the blueprint (such as `simplesoftwareio/simple-qrcode` which has been approved).
4. Caching production assets (`config:cache`, `route:cache`) in the dev environment.
