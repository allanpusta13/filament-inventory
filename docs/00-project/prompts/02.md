## 📂 Phase 02: Relational Databases & High-Precision Migrations

### Developer Instruction Prompt
Write database migrations implementing high-precision decimal scales, cascade deletions, and index paths, fully conforming to the **Pure Derived Stock of Truth Model** (dropping any physical `warehouse_stock` caching table):

1. **Migrations list**:
   * `products`: `sku` (unique), `name`, `category` (nullable), `reorder_point` (default 0).
   * `product_variants`: `product_id` (FK), `sku` (unique), `barcode` (nullable, unique), `name`, `base_unit_name`, `cost_price` (decimal 12,4), `sale_price` (decimal 12,4), `attributes` (json), `images` (json).
   * `product_unit_conversions`: `variant_id` (FK), `unit_name`, `base_unit_ratio` (integer), `is_default_purchase` (bool), `is_default_transfer` (bool).
   * `warehouses`: `code` (unique), `name`, `location`, `is_active` (bool, default true).
   * `product_prices`: `variant_id` (FK), `warehouse_id` (FK, nullable), `unit_name`, `price_type` (enum), `price` (decimal 12,4).
   * `stock_movements`: `variant_id` (FK), `warehouse_id` (FK), `type` (enum), `quantity` (signed integer), `related_movement_id` (FK, nullable), `reference_type` (nullable), `reference_id` (nullable), `reference_code` (nullable), `created_by` (FK). Add composite index on `(variant_id, warehouse_id)`.
   * `transfer_requisitions`: `reference_code` (unique), `from_warehouse_id` (FK), `to_warehouse_id` (FK), `status` (enum), `requested_by` (FK), `approved_by` (FK, nullable), `dispatched_by` (FK, nullable), `received_by` (FK, nullable), `requested_at`, `dispatched_at` (nullable), `completed_at` (nullable).
   * `requisition_items`: `requisition_id` (FK), `variant_id` (FK), `substitute_variant_id` (FK, nullable), `requested_unit_name`, `requested_unit_ratio`, `requested_qty`, `requested_base_qty`, `approved_unit_name` (nullable), `approved_qty` (nullable), `approved_base_qty` (nullable), `received_qty` (nullable).
   * `requisition_item_revisions`: `requisition_item_id` (FK), `user_id` (FK), `variant_id` (FK), `substitute_variant_id` (FK, nullable), `proposed_unit_name`, `proposed_qty`, `proposed_base_qty`, `negotiation_reason` (text).
   * `loss_ledgers`: `requisition_id` (FK), `variant_id` (FK), `warehouse_id` (FK), `lost_base_qty`, `damaged_base_qty`, `unit_cost_price` (decimal 12,4), `total_financial_loss` (decimal 15,4), `loss_category`.
   * `user_warehouse`: `user_id` (FK), `warehouse_id` (FK) as primary pivot.
2. **opening stock Seeding**: Set up a `DemoWorkflowSeeder` that seeds initial stock balances directly into the `stock_movements` table (using `type => 'receive'`) to represent initial on-hand quantities, avoiding the obsolete `warehouse_stock` table.

```bash
php artisan migrate:fresh --seed --class=DemoWorkflowSeeder
```
