## 📂 Phase 04: Concurrency-Resilient `InventoryService` & Loss Ledger Engine

### Developer Instruction Prompt
Write the transaction-safe service classes: **`App\Services\InventoryService`** and **`App\Services\LossLedgerService`**. Utilize database transactions and pessimistic locking (`lockForUpdate()`) to maintain ledger integrity under parallel operations:

1. **`recordMovement(...)`**: Creates append-only `stock_movements` log rows. Validates that incoming movements use positive parameters (Guardrail 5).
2. **`executeDirectTransfer(...)`**:
   * Accepts a variant, warehouses, packaging ratio, and notes.
   * Executes inside a database transaction, checking source stock availability dynamically.
   * Logs paired and balanced `transfer_out` and `transfer_in` rows.
3. **`dispatchRequisition(...)`**: Deducts items from the origin warehouse, moving them into virtual transit. Updates requisition status to `'dispatched'`.
4. **`receiveRequisition(...)`**: 
   * Credits items to the destination warehouse.
   * Computes shortfalls where physical intake is less than shipped numbers.
   * For every discrepancy, calls `LossLedgerService` to record an immutable loss snapshot at the variant's historic cost price.
   * Transitions status to `'completed'` or `'closed_with_loss'`.

```php
// app/Services/LossLedgerService.php
public function record(TransferRequisition $requisition, RequisitionItem $item, int $shortfallQty): LossLedger
{
    $costPrice = $item->variant->cost_price;
    return LossLedger::create([
        'requisition_id' => $requisition->id,
        'variant_id' => $item->variant_id,
        'warehouse_id' => $requisition->to_warehouse_id,
        'lost_base_qty' => $shortfallQty,
        'unit_cost_price' => $costPrice,
        'total_financial_loss' => $shortfallQty * $costPrice,
        'loss_category' => 'shortfall',
    ]);
}
```
