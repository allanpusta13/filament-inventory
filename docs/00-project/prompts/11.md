### Phase 11: Feature Delta, Bulk Exports & Playwright E2E Verification

#### Objective
Consolidate any outstanding system requirements—including trash recovery, bulk reporting, manual adjustments with robust audit rules, and soft-delete reservation restoration. Build a complete End-to-End (E2E) browser testing suite mapping the complete lifecycle from stock request through dispatch and scanned intake.

#### Requirements & Specs

##### 1. Logical Constraints & Action Delta

Ensure all structural elements are completed prior to browser testing:

*   **Soft Delete Recovery Scopes**:
    *   Enable `SoftDeletes` on `Product`, `ProductVariant`, and `TransferRequisition`.
    *   In the Filament listings table for these resources, declare `TrashedFilter::make()` to display Active vs. Trashed records.
    *   *Authorization Constraint*: Restrict the "Force Delete" and "Restore" table actions strictly to the `admin` role.
    *   *Reservation Restoration Assertions*: When a `confirmed` requisition is soft-deleted, verify that the `deleting` observer automatically returns the reserved stock back to the origin warehouse.

*   **Audited Manual Adjustments Validation**:
    *   Enforce that the manual stock adjustment slide-over on `WarehouseResource` requires an `audit_reason` with a minimum length of 15 characters and custom regex guards to block dummy patterns (like `"."`, `"test"`, or repetitions).

*   **Scan-to-Receive Tally Matching**:
    *   Inside the receiving dialog modal, dynamic math verification should be enforced: `good_qty + damaged_qty` must not exceed `shipped_qty`. Any delta is computed as a shortage and written to the `LossLedger` linked to a mandatory loss reason category.

*   **Bulk CSV Exports**:
    *   Implement `ExportBulkAction` on lists for `ProductResource`, `LossLedgerResource`, and `StockMovementResource` using Filament's built-in export actions to generate CSV matrices for audit purposes.

##### 3. Automated Browser Testing Specification (`tests/Browser/RequisitionLifecycleTest.php`)

Using Playwright or Laravel Dusk, construct a continuous workflow test tracing a multi-role transfer requisition lifecycle:

```php
namespace Tests\Browser;

use App\Models\User;
use App\Models\TransferRequisition;
use Tests\DuskTestCase;
use Laravel\Dusk\Browser;

class RequisitionLifecycleTest extends DuskTestCase
{
    /**
     * Test the continuous multi-stage physical-to-digital shipping pipeline.
     */
    public function test_complete_requisition_lifecycle_with_multiple_roles(): void
    {
        $this->browse(function (Browser $staff, Browser $fulfiller, Browser $recipient, Browser $auditor) {
            
            // -------------------------------------------------------------
            // Act I: Request Creation (Davao Staff)
            // -------------------------------------------------------------
            $staff->loginAs(User::where('email', 'staff.dvo@example.com')->first())
                ->visit('/admin/transfer-requisitions/create')
                ->select('from_warehouse_id', '1') // WH-MNL
                ->select('to_warehouse_id', '3')   // WH-DVO
                ->click('button[type="button"]:contains("Next")')
                ->click('button:contains("Add item")')
                ->select('items.0.variant_id', '1') // Premium Coffee Beans
                ->type('items.0.requested_qty', '10')
                ->click('button:contains("Submit Requisition")')
                ->waitForText('TRQ-')
                ->assertSee('requested');

            $requisition = TransferRequisition::latest()->first();
            $refCode = $requisition->reference_code;

            // -------------------------------------------------------------
            // Act II: Review & Counter-Offer (Manila Fulfilling Manager)
            // -------------------------------------------------------------
            $fulfiller->loginAs(User::where('email', 'manager.mnl@example.com')->first())
                ->visit("/admin/transfer-requisitions/{$requisition->id}/edit")
                ->click('button:contains("Counter-Offer")')
                ->type('items.0.approved_qty', '8') // Suggest a reduction
                ->click('button:contains("Send Counter Offer")')
                ->waitForText('under_review_requestor');

            // -------------------------------------------------------------
            // Act III: Counter-Offer Acceptance (Cebu Requesting Manager)
            // -------------------------------------------------------------
            $recipient->loginAs(User::where('email', 'manager.ceb@example.com')->first())
                ->visit("/admin/transfer-requisitions/{$requisition->id}/edit")
                ->click('button:contains("Accept & Confirm Quantities")')
                ->waitForText('confirmed');

            // -------------------------------------------------------------
            // Act IV: Shipment Dispatch (Manila Fulfilling Manager)
            // -------------------------------------------------------------
            $fulfiller->loginAs(User::where('email', 'manager.mnl@example.com')->first())
                ->visit("/admin/transfer-requisitions/{$requisition->id}/edit")
                ->click('button:contains("Dispatch Shipment")')
                ->waitForText('dispatched')
                ->assertSee('Download STN PDF');

            // -------------------------------------------------------------
            // Act V: QR Intake & Loss Logging (Cebu Requesting Manager)
            // -------------------------------------------------------------
            $recipient->loginAs(User::where('email', 'manager.ceb@example.com')->first())
                // Simulate QR scan url parameter trigger
                ->visit("/admin/transfer-requisitions/{$requisition->id}/edit?scan=1")
                ->waitForText('Reconcile & Receive Shipment')
                ->type('received_items.0.good_qty', '7') // 7 good
                ->type('received_items.0.damaged_qty', '1') // 1 damaged (1 lost short)
                ->select('received_items.0.loss_category', 'Damaged in Transit')
                ->click('button:contains("Receive Inventory")')
                ->waitForText('closed_with_loss');

            // -------------------------------------------------------------
            // Act VI: Read-Only Audit Scopes (Global Auditor)
            // -------------------------------------------------------------
            $auditor->loginAs(User::where('email', 'auditor@example.com')->first())
                ->visit('/admin/loss-ledgers')
                ->type('table_search', $refCode)
                ->waitForText($refCode)
                ->assertSee('1.0000') // Verify 1 unit recorded as damaged/lost
                ->assertDontSee('Edit')
                ->assertDontSee('Delete');
        });
    }
}
```
