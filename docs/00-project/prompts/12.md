## 📂 Phase 12: Eager-Loading Optimization & N+1 Loop Prevention

### Developer Instruction Prompt
Identify and eliminate database performance bottlenecks across all Filament resources by enforcing strict query eager-loading. You must ensure that index views and tabular pages execute with a flat, predictable query footprint regardless of record density:

1. **Eloquent Query Overrides**:
   * In each of your resource classes (Product, TransferRequisition, InTransit, StockMovement, LossLedger, Warehouse, and User), override the static **`getEloquentQuery()`** method.
   * Enforce explicit eager-loading (`parent::getEloquentQuery()->with([...])`) on all related models.
2. **Eager-Load Mappings**:
   * `ProductResource` -> Eager-load `['variants', 'variants.unitConversions']`.
   * `TransferRequisitionResource` -> Eager-load `['fromWarehouse', 'toWarehouse', 'requestedBy', 'items']`.
   * `InTransitResource` -> Eager-load `['requisition.fromWarehouse', 'requisition.toWarehouse', 'variant']`.
   * `StockMovementResource` -> Eager-load `['variant', 'warehouse', 'creator']`.
   * `LossLedgerResource` -> Eager-load `['requisition', 'variant', 'warehouse']`.
   * `WarehouseResource` -> Eager-load `['users', 'warehouseStocks']`.
   * `UserResource` -> Eager-load `['warehouses']`.
3. **Pest Verification Specs**:
   * Write dedicated integration tests utilizing DB query logs to assert that loading index pages triggers a flat number of queries, verifying complete safety against relational database loops.
