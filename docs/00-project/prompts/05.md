### Phase 05: Product Catalog Filament Resource

#### Objective
Construct the central administrative `ProductResource` in FilamentPHP v5 supporting multi-variant configurations, image libraries, barcode management, dynamic unit conversion rules, dual-mode grid/table interfaces, and trash recycling.

---

#### Requirements & Specs

##### 1. Main Resource Definition (`app/Filament/Resources/ProductResource.php`)

*   **Structure & Eager Loading**:
    To prevent severe N+1 database querying loops on the inventory listings, configure eager loading of variants and images directly inside the base query:
    ```php
    public static function getEloquentQuery(): \Illuminate\Database\Eloquent\Builder
    {
        return parent::getEloquentQuery()
            ->with(['variants'])
            ->withoutGlobalScopes([
                \Illuminate\Database\Eloquent\SoftDeletesScope::class,
            ]);
    }
    ```

*   **Dynamic Dual-View Catalog (Table Layout)**:
    Enables users to toggle seamlessly between a high-density tabular list and a responsive card visual layout:
    ```php
    public static function table(Table $table): Table
    {
        return $table
            ->columns([
                Tables\Columns\TextColumn::make('sku')
                    ->label('Product Family SKU')
                    ->bold()
                    ->searchable()
                    ->sortable(),
                Tables\Columns\TextColumn::make('name')
                    ->label('Product Name')
                    ->searchable()
                    ->sortable(),
                Tables\Columns\TextColumn::make('category')
                    ->badge()
                    ->color('gray')
                    ->searchable(),
                Tables\Columns\TextColumn::make('reorder_point')
                    ->label('Reorder Limit (Base)')
                    ->numeric()
                    ->sortable(),
                Tables\Columns\TextColumn::make('variants_count')
                    ->label('SKU Variants')
                    ->counts('variants')
                    ->badge(),
            ])
            ->contentGrid([
                'md' => 2,
                'xl' => 3,
            ]) // Supports visual grid toggle (contentGrid overrides list table when toggled in UI)
            ->filters([
                Tables\Filters\SelectFilter::make('category')
                    ->options([
                        'Beverages' => 'Beverages',
                        'Packaging' => 'Packaging',
                        'Raw Materials' => 'Raw Materials',
                    ]),
                // Soft-Delete Filter Controls
                Tables\Filters\TrashedFilter::make(),
            ])
            ->actions([
                Tables\Actions\EditAction::make(),
                Tables\Actions\DeleteAction::make(),
                Tables\Actions\RestoreAction::make(),
            ])
            ->bulkActions([
                Tables\Actions\BulkActionGroup::make([
                    Tables\Actions\DeleteBulkAction::make(),
                    Tables\Actions\RestoreBulkAction::make(),
                    Tables\Actions\ForceDeleteBulkAction::make(),
                ]),
            ]);
    }
    ```

##### 2. Variants Relation Manager (`app/Filament/Resources/ProductResource/RelationManagers/VariantsRelationManager.php`)

Allows managing SKUs, Barcodes, Pricing, and Uploads per variant.

*   **Micro-Unit Costing & Precision Handling**:
    To permit sub-cent micro-pricing inputs (e.g., \$0.0150 cost price per gram of coffee), configure decimal inputs to support high numeric precision:
    ```php
    Forms\Components\TextInput::make('cost_price')
        ->label('Base Unit Cost')
        ->numeric()
        ->required()
        ->step('0.0001') // Guardrail 1: Step attribute preventing browser submit rounding blocks
        ->prefix('$')
        ->minValue(0),

    Forms\Components\TextInput::make('sale_price')
        ->label('Base Unit Retail Price')
        ->numeric()
        ->required()
        ->step('0.0001')
        ->prefix('$')
        ->minValue(0),
    ```

*   **Dynamic Attributes & File Management**:
    *   *Barcode*: Unique identifier, required for scan integrations.
    *   *Attributes*: Custom key-value dictionary using Filament's `KeyValue` form builder (e.g., color, size, density).
    *   *Images*: Store file paths dynamically as a json array using FileUpload component.

---

##### 3. Conversions Relation Manager (`app/Filament/Resources/ProductResource/RelationManagers/ConversionsRelationManager.php`)

Defines conversions from the Base Unit to packaging levels (e.g. 1 Bag = 1,000 Pcs).

*   **Conversions Form Schema**:
    *   `unit_name`: Text field representing target packaging (e.g. `'Box'`, `'Pallet'`).
    *   `base_unit_ratio`: Integer multiplier greater than zero (e.g. `24` indicates `1 Box = 24 Base Units`).
    *   `is_default_purchase`: Toggle button to set as default incoming purchase order receipt packaging.
    *   `is_default_transfer`: Toggle button to set as default shipping packaging.

*   Confirm you can insert and submit an exact cost price of `$0.0150` on a variant row without browser validation warnings.
