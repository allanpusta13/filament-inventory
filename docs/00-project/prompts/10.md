## 📂 Phase 10: Scan-to-Receive Landing Page & Discrepancy Reconciliation

### Developer Instruction Prompt
Write the secure **Scan-to-Receive Controller** and the **Receipt Reconciliation Modal** to close out virtual transit loops cleanly:

1. **The Scan Route (`ScanReceiptController.php`)**:
   * Expose a GET route `/stn/{transferRequisition}/scan` pointing to `show()`. Apply the standard `signed` and `auth` middleware layers to enforce signature validation.
   * **The Landing Page**: The landing page must display a read-only list of dispatched items, acting as an interactive landing page rather than executing updates immediately upon navigation.
   * Restrict access checks so only authenticated users authorized at the destination warehouse can access the page.
2. **Reconciliation Modal & Verification Logic**:
   * On the confirm page, present a form containing an input repeater pre-populated with expected quantities.
   * **Discrepancy Logging**: Fulfillers can adjust quantities downward. If the physical intake is less than shipped levels, automatically calculate variances, trigger compliance reason prompts, and write write-offs to the `LossLedger` at the current unit cost price using `LossLedgerService`.
   * **Handling Omitted Items**: If an item is completely missing from the input scan payload, do not skip or omit it. Enforce a 0 received quantity count, calculate a 100% financial write-off, and write the loss log.
   * Call `InventoryService::receiveRequisition()` to credit destination stocks, log the loss aggregates, and transition the requisition status to `closed_with_loss` or `completed` in a single transaction.
