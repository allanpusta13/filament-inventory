### Phase 03: RBAC Roles, Policy Architecture & User Accounts Seeder

#### Objective
Establish a secure, role-based authorization structure using standard Laravel Policies bound to Filament Resources. Restrict branch-level access using multi-warehouse pivot scopes, seed a comprehensive set of testing user accounts, and implement custom policy-level handling to avoid raw 403 authorization screens for logged-out or misaligned staff scanning STNs.

---

#### Requirements & Specs

##### 1. User & Role Seeder (`database/seeders/UserRoleSeeder.php`)
Populate standard administrative and operational test user accounts. Use `bcrypt('password')` for all accounts to secure baseline credentials:

*   **System Admin** (`admin@example.com`):
    *   *Role*: `admin`
    *   *Warehouse Pivot*: All Warehouses (`WH-MNL`, `WH-CEB`, `WH-DVO`)
*   **Manila Branch Manager** (`manager.mnl@example.com`):
    *   *Role*: `branch_manager`
    *   *Warehouse Pivot*: `WH-MNL`
*   **Cebu Branch Manager** (`manager.ceb@example.com`):
    *   *Role*: `branch_manager`
    *   *Warehouse Pivot*: `WH-CEB`
*   **Davao Warehouse Staff** (`staff.dvo@example.com`):
    *   *Role*: `warehouse_staff`
    *   *Warehouse Pivot*: `WH-DVO`
*   **Inventory Auditor** (`auditor@example.com`):
    *   *Role*: `auditor`
    *   *Warehouse Pivot*: All Warehouses *(Read-Only Access)*

---

##### 2. Scoped Laravel Authorization Policies

Policies are registered in the application's AuthServiceProvider and bound automatically to Filament resources.

*   **`TransferRequisitionPolicy`** (`app/Policies/TransferRequisitionPolicy.php`):
    *   *viewAny*: 
        *   `admin` or `auditor` => true (unrestricted visibility).
        *   `branch_manager` or `warehouse_staff` => restrict query to records where `from_warehouse_id` or `to_warehouse_id` matches any warehouse ID the user is assigned to via pivot.
    *   *view*: 
        *   `admin` or `auditor` => true.
        *   `branch_manager` or `warehouse_staff` => true *only* if the specific requisition's `from_warehouse_id` or `to_warehouse_id` matches the user's assigned warehouse IDs.
        *   *Audit Safe-Guard*: If a user scans an STN QR code for a warehouse they are *not* assigned to, do *not* fail with a raw unhandled Laravel 403 error screen. Intercept the check, and instead redirect back to the central dashboard with an explicit Filament notice: *"Access Denied: Requisition assigned to external warehouse."*
    *   *create*:
        *   `admin`, `branch_manager`, or `warehouse_staff` => true.
        *   `auditor` => false (read-only).
    *   *update* (negotiating, editing drafts):
        *   `admin` => true (full override).
        *   `branch_manager` => true *only* if the requisition involves their warehouse and the status allows review (e.g. `under_review_fulfiller` or `under_review_requestor`).
        *   `warehouse_staff` => true *only* if the requisition status is `'draft'`, they created it, and it targets their warehouse.
        *   `auditor` => false.
    *   *delete* (soft-deleting):
        *   `admin` => true.
        *   `branch_manager` => true *only* if the requisition is a `'draft'` and belongs to their warehouse.
        *   `warehouse_staff` or `auditor` => false.

*   **`StockMovementPolicy`** (`app/Policies/StockMovementPolicy.php`):
    *   *viewAny*:
        *   `admin` or `auditor` => true.
        *   `branch_manager` or `warehouse_staff` => restricted strictly to movements occurring within their assigned warehouse IDs.
    *   *create* / *update* / *delete*:
        *   *General Rule*: Handled exclusively by the secure `InventoryService`. High-level write commands via the UI are disabled for all roles except `admin` for emergency overrides, which requires a mandatory audit note.

*   **`LossLedgerPolicy`** (`app/Policies/LossLedgerPolicy.php`):
    *   *viewAny* / *view*:
        *   `admin` or `auditor` => true.
        *   `branch_manager` => restricted strictly to losses occurring at their assigned warehouse IDs.
        *   `warehouse_staff` => false (staff should not inspect accumulated financial ledger profiles).
    *   *create* / *update* / *delete*:
        *   `admin` => true (unrestricted override).
        *   All other roles => false (losses are posted automatically during physical receiving scans).

*   **`ProductPolicy`** (`app/Policies/ProductPolicy.php`):
    *   *viewAny* / *view*:
        *   All authenticated roles => true.
    *   *create* / *update* / *delete*:
        *   `admin` => true.
        *   All other roles => false (prevents branch-level personnel from editing central SKUs or conversions).

##### 3. Registering the Security Seeds
In `database/seeders/DatabaseSeeder.php`, call the baseline seeds in sequence:
```php
public function run(): void
{
    $this->call([
        WarehouseAndCatalogSeeder::class,
        UserRoleSeeder::class,
    ]);
}
```
